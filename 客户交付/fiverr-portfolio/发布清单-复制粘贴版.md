| 表单字段 | 填什么 | 备注 |
|---|---|---|
| **Project name** | 见 §0.6 的 ≤50 字项目名 | 上限 **50 字符** |
| **Industry** | 从下拉选，**最多 6 个** | 建议按项目挑：`E-commerce & Retail` / `Food & Beverage` / `Automotive` / `Beauty & Wellness` / `Technology` |
| **Project duration** | 选最接近的下拉项 | 建议 `1-3 months` |
| **Project cost** | 填合理数字（$） | 建议 `1500`；不想暗示付费项目可留空 |
| **Project started on** | MM / YY | 填你实际开始改造的月份，如 `09 / 2026` |
| **Project description** | 粘本文档对应项目区块的 **Description** | 上限 **1400 字符**（我们的是 900–1100，够用） |
| **Attachments** | **第 1 个文件 = 封面** → `covers/cover-*.png`；之后再追加原始截图 | 官方建议缩略图 1024×768 / 4:3 |

## §风险与合规（发布前自查）

1. **署名话术**：每个 Description 都已含 *"based on open-source `bahar`, original author attribution preserved"* —— **不要删**。
2. **禁贴源码**：只发布界面截图，绝不贴 Java/前端代码或仓库地址。
3. **禁泄露凭据**：描述与图片里**不要出现** `bahar / 123456`、`999999` 万能码、`127.0.0.1:8081~8084`、内网地址。
4. **ATS 禁用词**：描述里避免 `guaranteed / #1 / best / 100% / cheapest / fastest` 这类绝对化词；图片里不要放联系方式或二维码。
5. **图片数量**：每个项目 ≤5 张，第 1 张务必是 `covers/cover-*.png`（4:3 不留白，缩略图更干净）。
6. **账号上限**：Fiverr 全账号最多 10 个 Portfolio 项目，本方案只用 4 个，留有余量可后续补技术亮点项目。
