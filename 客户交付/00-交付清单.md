## 三、截图复现方式（供内部使用）

截图脚本位于 `deploy/tmp/`（不随客户交付）：

| 脚本 | 用途 |
|---|---|
| `admin_screenshot.sh` | 后台 Admin 21 张（取图形验证码 → 登录 → 注入 token → 逐模块截图） |
| `member_login.py` + `member_screenshot.sh` | 会员端 20 张（API 登录拿 token → 注入 `localStorage['AccessToken']` → 分包路由截图） |
| `shoot_member_with_backend.sh` | 会员端截图的“一键跑”：先起零售后端（8081）并等就绪，再执行 `member_screenshot.sh`（因进程随调用结束回收，起服务与截图必须在同一次调用内完成） |
| `cashier_captcha.py` + `cashier_screenshot.sh` | 收银端 8 张（重建本地 web 包 → 驱动真实登录表单 → 逐路由截图） |

> 复现前提：四套后端已启动（`deploy/start-all.sh`）、Redis 与 MySQL 可用、脚本内已绕过本机全局代理。
>
> 另：重拍「18-数据统计」前，需先对目标库执行 `deploy/db/22-refresh-order-dates.sql` 做数据保鲜，
> 否则统计页与运营走势会因演示订单过期而显示 0 / 空白。
