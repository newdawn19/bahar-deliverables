# 04 · 稳定性与安全性说明

> **本文档目的**：向客户说明 bahar 四行业矩阵站的生产级架构能力，让您「放心使用」；同时**诚实标注**当前交付为演示形态，并给出上线前必须补齐的生产化建议，避免被误认为已具备全部生产防护。

---

## 一、稳定性（Stability）

### 1.1 技术底座

| 层面 | 采用方案 | 说明（均可在源码 / 配置中核对） |
| --- | --- | --- |
| 应用框架 | **Spring Boot + Jetty** | `server.jetty.max-http-header-size` 已按需放大；内嵌容器，单 jar 直接运行 |
| 关系型数据库 | **MySQL** | `spring.datasource` 走 JDBC，`type=com.zaxxer.hikari.HikariDataSource` |
| 连接池 | **HikariCP** | 默认高性能连接池，提供连接复用与超时保护 |
| 缓存 / 会话 | **Redis** | `spring.redis`（lettuce 池化）；`spring.session.redis.namespace` 存放会话；Token 与短信验证码亦存 Redis |
| 本地缓存 | **Ehcache** | `spring.cache.type=ehcache`，策略见 `classpath:ehcache.xml`，缓解热点读 |
| 持久层 | **MyBatis-Plus** | 通用 CRUD + 分页插件，减少手写 SQL |
| 日志与审计 | **SLF4J + `TActionLogAop`** | 后台关键写操作经 `@OperationServiceLog` 切面自动落地 `t_action_log` |

### 1.2 可水平扩展点

- **无状态服务，可多实例**：登录态以 `Access-Token` 存于 Redis（`SESSION_USER` / `SESSION_ADMIN_USER`），应用节点本身无会话粘连，前端可经负载均衡（Nginx）横向扩容。
- **四行业物理隔离**：零售 / 汽车 / 餐饮 / 康养四套后端使用**独立数据库与独立 Redis DB 序号**（db0~db3）、独立端口（8081~8084），互不干扰，单行业故障不波及其他行业。
- **资源与计算解耦**：上传文件走对象存储（OSS）或本地磁盘（`images.root`），与计算节点解耦；支付 / 短信 / 微信等外部调用均有独立 Service 封装，便于替换与限流。

### 1.3 数据备份建议

| 对象 | 建议 |
| --- | --- |
| MySQL | 每日定时全量 + 增量 binlog 备份，保留 ≥ 7 天；定期演练恢复 |
| Redis | 开启 RDB + AOF 持久化；Token / 验证码为易失数据，丢失仅影响在线会话，可接受 |
| 文件（本地磁盘 `images.root` 或 OSS） | 本地模式定期同步至异地 / 对象存储；OSS 开启版本与跨区域复制 |
| 配置 | `application.yaml`、密钥、证书纳入版本库 / 配置中心并加密保管 |

## 二、安全性（Security）

| 能力 | 实现位置 | 说明 |
| --- | --- | --- |
| **登录图形验证码** | `CaptchaService` + `CaptchaConfig`（Kaptcha）、`ClientCaptchaController` / `BackendLoginCaptchaController` | 注册、登录、发送短信前必须校验图形码（`checkCodeByUuid`），防机器刷接口 |
| **密码 SHA256 + Salt 存储** | `MemberService`（`setPassword` / `verifyPassword`，`mt_user.password` + `mt_user.salt`） | 密码加盐哈希存储（`SHAUtil.sha256(password + salt)`），不直接落明文；`verifyPassword` 先按 SHA256 比对、并兼容历史 MD5 库校验；改密走旧密码校验 |
| **Access-Token 拦截器鉴权** | `ClientUserInterceptor`（会员端）、`AdminUserInterceptor`（后台） | 所有 `/clientApi/**`、`/backendApi/**` 请求校验 `Access-Token`，并校验商户是否过期（过期清 Token 返回 1003） |
| **基于商户 / 门店 / 员工的 RBAC** | `AccountService` / `DutyService` / `SourceService`、`@PreAuthorize("@pms.hasPermission('xxx:edit')")`、`AdminRoleEnum` | 后台账号归属商户 / 门店，菜单与操作权限按角色（`t_duty` / `t_source`）隔离，越权返回 403 |
| **CORS 跨域配置** | `CORSFilter`（`OncePerRequestFilter`） | 按请求 `Origin` 动态回写 `Access-Control-Allow-Origin`，放行头含 `Access-Token / platform / storeId / merchantNo / isWechat` 等 |
| **MyBatis-Plus 防 SQL 注入** | 全量使用 `#{}` 预编译参数 | 杜绝拼接 SQL；分页与条件构造器基于 MyBatis-Plus Wrapper |
| **输入校验** | `BusinessCheckException`、`PhoneFormatCheckUtils.isChinaPhoneLegal` 等 | 手机号格式、必填项、业务状态在 Service 层统一校验并友好报错 |
| **操作审计日志** | `TActionLogAop`（`@OperationServiceLog` 切面 → `t_action_log`） | 记录操作人、商户、门店、URL、参数、耗时、客户端 IP 与 UA，便于追溯 |

## 三、诚实标注：当前为「演示形态」，上线前需补齐（上线建议）

> 以下事项**当前未在该交付中默认具备**，请在正式投产前逐项落实，避免安全与可用性盲区。

| 类别 | 现状（演示） | 上线建议 |
| --- | --- | --- |
| 传输安全 | 演示为 HTTP（默认 `http://127.0.0.1:8081~8084`） | 全站启用 **HTTPS / TLS**，微信 / 支付宝回调与 JS-API 均强制 HTTPS 域名 |
| 网络暴露 | 端口直连，无边界防护 | 前置 **防火墙 / 安全组 / WAF**，仅放行必要端口与路径；后台 `/admin` 与 API 建议置于内网或加 IP 白名单 |
| 密钥管理 | 部分密钥写在 `application.yaml` / 环境变量 | 接入**配置中心 / 密钥管理服务（KMS）**，密钥加密存储，避免明文入库或入版 |
| 口令策略 | 演示账号口令固定 | 强制**初始改密、定期改密（如 90 天）**、复杂度策略；禁用默认账号 |
| 数据架构 | 单库单实例演示 | 生产建议**读写分离、主从备份**；高并发行业可评估分库分表与 Redis 集群 |
| 限流防刷 | 验证码 + 基础校验 | 对短信、登录、下单等接口增加**限流 / 防重放 / 风控**（如 Redis 计数、滑动窗口） |
| 日志与监控 | 本地日志 + `t_action_log` | 接入**集中日志（ELK）、指标监控（Prometheus）、告警**；对审计日志做**敏感字段脱敏** |
| 演示数据 | 含演示商户 / 商品 / 会员 / 固定码 | 上线前**清理演示数据**，初始化客户真实基础档案与权限 |

> **结论**：系统架构与代码实现已具备生产级的基础稳定性与多层安全防护（无状态可扩展、RBAC、Token 鉴权、加盐密码、审计日志、预编译防注入）。在补齐上述「上线建议」后，即可承载正式商业运营。
